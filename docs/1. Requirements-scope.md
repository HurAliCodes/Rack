## 1. Product Vision

### Product Name 
Rack

### Vision
Create an AI-powered personal wardrobe that helps users:

- Digitize their clothes
- Organize their wardrobe
- Create outfits
- Discover new outfit combinations
- Plan what to wear
- Receive AI styling advice
- Virtually try on clothes
- Reduce unnecessary shopping
- Eventually become a complete AI fashion assistant

> **Note:** This is more than a "closet app." The long-term vision is an AI stylist platform.

---

## 2. Target Users (MVP)

### Primary User
Individual users managing their own wardrobe.

### Not Building For (V1)
- Fashion brands
- Clothing stores
- Teams
- Families
- Influencers
- Stylists

> These can be added later without changing the core architecture.

---

## 3. MVP Goals

### Core Problem Statement
> "I want to know what clothes I own and get outfit recommendations without digging through my closet."

### MVP Capabilities
- Create an account
- Upload clothing photos
- Organize clothes into categories
- Search and filter clothes
- Create outfits
- Mark favorite outfits
- Track clothing usage (recently worn)
- View wardrobe statistics

## 5. Non-Functional Requirements

### 5.1 Security
- JWT access tokens
- Refresh token rotation
- Password hashing with Argon2
- Input validation using Zod
- Rate limiting
- Secure HTTP headers
- CSRF protection (future)
- SQL injection protection via Prisma
- XSS mitigation
- Environment variable management

### 5.2 Performance
- Pagination for all list endpoints
- Indexed database columns
- Optimized image delivery
- Lazy loading
- Query optimization

### 5.3 Scalability
- Stateless backend
- Horizontal scaling
- Cloud object storage
- Modular architecture
- AI services isolated from core business logic

### 5.4 Maintainability
- Feature-based modules
- Service layer
- Repository pattern where it adds value
- Centralized error handling
- Consistent API responses
- Strong typing

### 5.5 Reliability
- Structured logging
- Health check endpoint
- Graceful shutdown
- Database migrations
- Automated backups (deployment phase)

## 6. Constraints

| Constraint | Description |
|------------|-------------|
| **Deployment Model** | Single-tenant SaaS (each user has a separate wardrobe, but all users share the same application and database) |
| **Primary Database** | PostgreSQL |
| **Image Storage** | Cloudinary |
| **Backend Framework** | Express.js |
| **Frontend Framework** | React (later) |
| **AI Integration** | Must be modular |
| **Mobile** | Mobile app comes later and will consume the same API |

---

## 7. Assumptions

To avoid over-engineering the MVP, we assume:

1. Each clothing item has one primary image
2. One account belongs to one person
3. Users cannot collaborate on wardrobes in V1
4. AI processing can happen asynchronously in the future
5. Images are stored externally, not in PostgreSQL

---

## 8. Architecture Decisions Made Today

By the end of this milestone, we've committed to:

- ✅ Backend-first development
- ✅ API-first design
- ✅ Feature-based architecture
- ✅ AI-ready modular design
- ✅ Stateless authentication
- ✅ External object storage
- ✅ PostgreSQL + Prisma
- ✅ Production-ready mindset from day one

| Social feed | Feature creep |
| Public profiles | Feature creep |
| Real-time chat | Not needed for MVP |
| Shopping marketplace | Future phase |
| Payments and subscriptions | Future phase |
| AI virtual try-on | Requires extensive research |
| Offline synchronization | High complexity |
| Team/family wardrobes | Not primary user |
